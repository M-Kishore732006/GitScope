================================================================================
                    GITSCOPE - PROJECT ANALYSIS & ARCHITECTURE
================================================================================

1. PROJECT OVERVIEW & OBJECTIVE
--------------------------------------------------------------------------------
GitScope is an institutional full-stack platform (MERN + Socket.io) designed for
universities and technical colleges to monitor, evaluate, visualize, and 
gamify students' GitHub coding activity and open-source contributions.

Key Institutional Challenges Solved:
- Eliminates manual verification of individual student GitHub profiles.
- Provides an objective, metric-driven contribution scoring algorithm.
- Delivers multi-tier gamification, milestone badges, and leaderboards to 
  encourage sustained coding consistency.
- Equips faculty mentors with supervisory dashboards, at-risk early intervention 
  alerts, and side-by-side student comparison tools.
- Provides administrators with institutional analytics, audit logging, and 
  configurable scoring engine rules.
- Incorporates real-time peer/mentor chat and AI-driven code health analysis.


2. TECHNOLOGY STACK
--------------------------------------------------------------------------------
Frontend (Client):
- Framework: React.js (v19) SPA
- Routing: React Router DOM (v7) with Protected & Role-Guarded Routes
- Real-Time Communication: Socket.io Client (v4.8)
- UI & Styling: Bootstrap 5, Custom SaaS Theme, ThemeContext (Dark / Light Mode)
- Data Visualizations: Recharts (Line, Bar, Pie, Area, Radar) & SVG Heatmap
- Icons: React Icons (FontAwesome 'Fa', Bootstrap Icons 'Bs')
- HTTP Client: Axios with JWT Authorization Interceptors

Backend (Server):
- Runtime & Framework: Node.js with Express.js (v5)
- Real-Time Engine: Socket.io Server (v4.8) for live messaging, presence, alerts
- File Uploads: Multer for chat media and document attachments
- Security & Middleware:
  * Helmet (HTTP header security)
  * Express Rate Limit (API throttling: 500 req / 15 min)
  * CORS (Secure cross-origin origin filtering)
  * Bcrypt (10-round salted password hashing)
  * JSON Web Tokens (JWT) for stateless authentication
- Scheduled Jobs: node-cron (Automated 12-hour institutional sync cycle)

Database & Storage:
- Database: MongoDB (Atlas Cloud / Local)
- Object Modeling: Mongoose ODM (v9) with schema validation, hooks, and indexes

External Integrations:
- GitHub GraphQL API v4: Single-query bulk fetch for profile, repositories, 
  star counts, commit calendars, and merged PR counts.
- GitHub REST API: Real-time public event activity logs and event feeds.
- GitHub OAuth 2.0: One-click secure student account linking.


3. USER ROLES & ACCESS CONTROL (RBAC)
--------------------------------------------------------------------------------
1. STUDENT:
   - Authentication: Register/login with roll number, department, year, section.
   - GitHub Integration: Link account via OAuth 2.0 or direct username input.
   - Telemetry Dashboard: Track commits, PRs (open/merged), issues, stars, streaks.
   - Visual Analytics: Commit trends, language breakdown, contribution heatmaps.
   - Gamification: Multi-tier level progression (Bronze to Legend) & achievement badges.
   - Skill & Code Health Radar: 6-dimensional AI evaluation (Consistency, 
     Collaboration, Diversity, Impact, Hygiene, Documentation) with guidance.
   - Leaderboards: Global and Departmental rankings with personal rank highlight.
   - Public Portfolio: Shareable public profile (/portfolio/:username) showcasing stats.
   - Real-Time Chat: Private messaging with assigned mentors, peers, and group channels.
   - Profile Settings: Manage personal info, change password, or request deletion.

2. STAFF / FACULTY MENTOR:
   - Roster Management: View assigned students filtered by department, year, status.
   - Supervisory Dashboard: Metrics on connected profiles, activity, and totals.
   - At-Risk Analytics & Early Intervention: Automatically identifies inactive, 
     unconnected, or low-performing students; dispatch early warning notices.
   - Student Comparison: Side-by-side comparison of up to 4 students across key metrics.
   - Live Activity Feed: Audit real-time commit actions and repository creations.
   - On-Demand Sync: Trigger manual GitHub synchronization for individual students.
   - Reports: Export student performance summaries to CSV or JSON formats.
   - Direct Communication: Real-time chat with assigned students and faculty groups.

3. ADMINISTRATOR:
   - Institution Overview: Aggregate commit/PR stats, department distribution, 
     monthly activity curves, and platform health telemetry.
   - User Management: Full CRUD for staff and students, status toggles (active/
     inactive/deactivated), password resets, and batch student-to-staff assignments.
   - GitHub Accounts Central: Monitor sync statuses, trigger individual or bulk 
     sync ('Sync All'), and disconnect erroneous student accounts.
   - Scoring Rules Engine: Configure scoring weights for commits, open/merged PRs, 
     issues, code reviews, repositories, and inactivity threshold days.
   - Score Recalculation: Batch re-evaluate all student scores and rankings instantly.
   - Audit Logging & Governance: Immutable chronological log tracking actor IDs, 
     roles, actions, target entities, IP addresses, and timestamps.
   - Platform Communication: Broadcast system announcements and participate in chat.
   - Global Search: Instant lookup across students, staff, and repositories.


4. CORE MODULES & BUSINESS LOGIC
--------------------------------------------------------------------------------
A. GitHub Synchronization Engine (githubService.js):
   - Executes optimized GraphQL queries against api.github.com/graphql.
   - Extracts follower metrics, repository snapshots, star/fork totals, language 
     distribution, and weekly continuous contribution calendars.
   - Queries public REST event streams for recent push/PR activity feeds.
   - Calculates consecutive daily contribution streaks with current-day grace period.
   - Updates student GithubStats document in MongoDB.

B. Dynamic Scoring Engine (scoreService.js):
   - Computes student Contribution Score based on customizable institutional weights:
     Score = (Commits * W_commit) + 
             (Merged PRs * W_mergedPR) + 
             (Open PRs * W_openPR) + 
             (Issues * W_issue) + 
             (Reviews * W_review) + 
             (Repositories * W_repo) + 
             (Total Stars * 2) + 
             (Streak Days * 2)
   - Recomputes institutional ranks and updates overallRank and departmentRank.

C. Gamification & Achievement Engine (achievementService.js):
   - Milestone Badges: First Commit, 100/500/1000 Commits, First PR, First Merge, 
     1-Week Streak, 30-Day Streak, 100-Day Streak.
   - Tier Progression:
     * Bronze:    < 100 points
     * Silver:    100 - 499 points
     * Gold:      500 - 2,499 points
     * Platinum:  2,500 - 9,999 points
     * Diamond:   10,000 - 49,999 points
     * Legend:    50,000+ points

D. AI Code Health & Skill Radar (aiCodeHealthService.js):
   - Evaluates 6 key engineering telemetry dimensions (0-100 scale):
     1. Consistency & Velocity (commit frequency & streak durability)
     2. Open Source Collaboration (merged PRs, forks, issue engagements)
     3. Tech Stack Versatility (language variety and breadth)
     4. Project Quality & Impact (stars, repo depth, structure)
     5. Code Hygiene (commit regularity and push frequency)
     6. Documentation Completeness (README coverage and repo descriptions)
   - Generates overall health score, letter grade (A+, A, B, C, D), and 
     actionable AI guidance tips for student improvement.

E. Real-Time Chat & Collaboration Engine (socket.js & chatController.js):
   - Socket.io authenticated connection with JWT validation.
   - Conversation Modes: Private (1-on-1 direct), Group, and Global channel.
   - Features: Real-time message push, presence status (online/offline/lastSeen), 
     typing indicators, message delivery receipts, read receipts, and media uploads.

F. At-Risk Analytics & Early Warning System (staffController.js):
   - Segregates students by risk level: High Risk, Moderate Risk, Healthy, Not Connected.
   - Evaluates inactivity threshold, contribution volume, and account connection status.
   - Enables mentors to send targeted warning notifications directly to student dashboards.

G. Background Synchronization Cron (githubCron.js):
   - Automated node-cron job executing every 12 hours (0 0,12 * * *).
   - Iterates through all linked student accounts with 2-second rate-limiting delay.
   - Automatically refreshes stats and updates leaderboards upon completion.


5. DATABASE MODELS (MONGOOSE SCHEMAS)
--------------------------------------------------------------------------------
1. User (models/User.js):
   - username, fullName, rollNumber (unique, sparse), email (unique), phoneNumber, password.
   - role: ['student', 'teacher', 'admin']
   - status: ['active', 'inactive', 'deactivated']
   - department, year, section, githubUsername, githubLinked.
   - assignedStaff (Ref -> User), assignedStudents ([Ref -> User]).
   - isOnline, lastSeen, lastLogin, mustChangePassword.

2. GithubStats (models/GithubStats.js):
   - user (Ref -> User), githubUsername, followers, following.
   - totalRepositories, totalCommitContributions, totalPullRequests, mergedPullRequests.
   - totalIssueContributions, totalStars, totalForks, reviews, contributionStreak.
   - contributionScore, overallRank, departmentRank, level.
   - achievements: [{ name, description, earnedAt }]
   - languageUsage: [{ language, count }]
   - repositoriesList: [{ name, url, description, stars, forks, primaryLanguage }]
   - contributionCalendar: [{ date, count }]
   - recentActivity: [{ type, repoName, action, createdAt }]
   - syncStatus: ['Connected', 'Not Connected', 'Syncing', 'Sync Failed']

3. Conversation (models/Conversation.js):
   - type: ['private', 'group', 'global']
   - name, description, groupAdmin (Ref -> User), groupAvatar.
   - participants: [Ref -> User]
   - lastMessage (Ref -> Message), lastMessageAt, unreadCounts (Map).

4. Message (models/Message.js):
   - conversation (Ref -> Conversation), sender (Ref -> User).
   - messageType: ['text', 'image', 'file'], content.
   - file: { filename, storedName, path, mimetype, size }
   - status: ['sending', 'sent', 'delivered', 'read', 'failed']
   - deliveredTo: [{ user, deliveredAt }], readBy: [{ user, readAt }]

5. SystemSettings (models/SystemSettings.js):
   - commitPoints, prPoints, mergedPrPoints, issuePoints, reviewPoints, repoPoints.
   - inactivityThresholdDays (default: 14), autoSyncFrequencyHours (default: 24).

6. AuditLog (models/AuditLog.js):
   - user (Ref), userEmail, userRole, action, target, description, ipAddress, createdAt.

7. Notification (models/Notification.js):
   - title, message, type ('info'|'warning'|'success'|'danger'), category, isRead.


6. KEY API ROUTE ARCHITECTURE
--------------------------------------------------------------------------------
Authentication (/api/auth):
- POST /register               : Student self-registration
- POST /login                  : JWT authentication and role-specific redirect info

Student Endpoints (/api/student) [Protected: Student]:
- GET  /dashboard              : Personal telemetry, rankings, and recent activity
- POST /github/link            : Direct username account link
- POST /github/oauth           : OAuth token exchange and account link
- POST /github/unlink          : Disconnect GitHub account
- POST /github/refresh         : On-demand telemetry sync
- GET  /repositories           : Repository catalog with metrics
- GET  /achievements           : Unlocked badges and tier progress
- GET  /leaderboard            : Overall and departmental standings
- GET  /ai-code-health         : Skill radar telemetry and AI insights
- GET  /public/:username       : Public portfolio profile (Open route)

Staff Endpoints (/api/staff) [Protected: Teacher/Staff]:
- GET  /dashboard              : Mentor supervision overview and quick metrics
- GET  /students               : Assigned student roster with filters
- GET  /students/:id           : Detailed student profile modal data
- POST /students/:id/sync      : On-demand sync for an assigned student
- GET  /monitoring             : Live student activity stream
- GET  /at-risk                : At-risk analytics and inactivity detection
- POST /at-risk/warning        : Dispatch intervention warning notice to student
- GET  /compare                : Multi-student comparative analysis (up to 4)
- GET  /rankings               : Leaderboard filtered by assigned students
- GET  /analytics              : Aggregate student cohort metrics
- GET  /reports/generate       : CSV / JSON performance report generator

Admin Endpoints (/api/admin) [Protected: Admin]:
- GET  /dashboard              : Institution-wide performance overview
- GET  /staff                  : Faculty directory with status & assigned count
- POST /staff                  : Create staff account
- PUT  /staff/:id              : Update staff profile / Reset password
- POST /staff/:id/assign-students : Bulk allocate students to faculty mentor
- GET  /students               : Student directory with search, filter, status
- PUT  /students/:id/status    : Toggle student account status
- GET  /github/accounts        : Central GitHub account monitor
- POST /github/sync-all        : Trigger batch institutional synchronization
- GET  /settings               : View scoring weights and configuration
- PUT  /settings               : Update scoring weights
- POST /settings/recalculate-scores : Batch recalculate institutional scores
- GET  /audit-logs             : Query governance audit records
- GET  /search                 : Global search across students, staff, repos

Chat & Messaging Endpoints (/api/chat) [Protected]:
- GET  /contacts               : List eligible messaging contacts
- GET  /conversations          : List user conversations with unread counts
- GET  /conversations/global   : Get or initialize global community channel
- POST /conversations/private  : Create or retrieve 1-on-1 private chat
- POST /conversations/group    : Create group conversation
- GET  /conversations/:id/messages : Retrieve paginated message history
- POST /conversations/:id/messages : Send message in conversation
- POST /upload                 : Upload attachment file/image (Multer)

8. LOCAL SETUP & QUICKSTART
--------------------------------------------------------------------------------
Prerequisites:
  - Node.js (v18 or higher) & npm
  - MongoDB database instance (Atlas Cloud URI or local mongod)
  - GitHub Personal Access Token (PAT) for backend GraphQL queries
  - GitHub OAuth Application (Client ID & Secret) for student OAuth linking

Environment Configuration (server/.env):
  PORT=5000
  MONGODB_URI=<your_mongodb_connection_string>
  JWT_SECRET=<your_jwt_secret_key>
  ADMIN_EMAIL=admin@institution.edu
  ADMIN_PASSWORD=<secure_admin_password>
  GITHUB_TOKEN=<github_personal_access_token>
  GITHUB_CLIENT_ID=<github_oauth_client_id>
  GITHUB_CLIENT_SECRET=<github_oauth_client_secret>
  FRONTEND_URL=http://localhost:3000

Step 1: Start Backend
  $ cd server
  $ npm install
  $ npm run dev        # Starts server on http://localhost:5000 (nodemon)

Step 2: Start Frontend
  $ cd client
  $ npm install
  $ npm start          # Starts React app on http://localhost:3000
